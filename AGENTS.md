# Инструкции для работы с репозиторием

## Язык и исходные требования

- Общайся с пользователем на русском. Комментарии и докстринги пиши на русском.
- Требования проекта изложены ниже и в `README.md`; аппаратные настройки находятся в `config.py`.

## Проект и структура

- Цель — анемометр на основе дифференциального давления трубки Пито: MicroPython, ESP32, плата LILIGO-TGALL с SIM800, два BMP280 по адресам I²C `0x76` и `0x77`.
- `stl/lower.stl` — геометрия аэродинамического профиля.
- `examples/main_sim7000.py` — рабочий пример для другой конфигурации: T-SIM7000G, SIM7000, Beeline и BLE-датчик. Используй его как источник приёмов инициализации, MQTT и завершения работы; параметры платы, AT-команды и настройки оператора требуют проверки для SIM800 и T2 Russia.
- `main.py` — точка входа, `app.py` — цикл и асинхронный опрос, `config.py` — настройки, `board.py` — питание и батарея, `bmp280.py` — драйвер, `sim800.py` — встроенные MQTT/HTTP через AT, `telemetry.py` — усреднение и расчёты, `remote_settings.py` — проверка JSON, `heater.py` — оттаивание и ограничение по RTC.
- `tests/` — проверки на CPython с имитацией аппаратных модулей. Зависимости примера `utilities.py` и `aioble` для основной прошивки не нужны.

## Требуемое поведение прошивки

- Измерять показания обоих BMP280 в течение минуты в отдельной асинхронной задаче, параллельно пробуждая модем и устанавливая MQTT-соединение.
- Передавать расчётную скорость ветра с учётом профиля, усреднённые давление и температуру, остаток батареи. Настройки MQTT и топик `fluger_p` указаны в `config.py`.
- Использовать встроенный MQTT модема через AT-команды. Точная версия прошивки неизвестна; не подменять его программным MQTT-клиентом без указания пользователя.
- Читать JSON из `http://212.34.149.112:80/flugerp.txt`: `sleep_minutes` и объект `heater` с `enabled` и `duration_s`. Пример находится в `flugerp.example.json`. При ошибке применять пять минут сна и выключенный нагрев.
- Оттаиватель управляется через транзисторный ключ на GPIO19, датчики питаются через GPIO18. Нагрев разрешён только при достоверном напряжении батареи не ниже 3.3 В, не чаще одного старта за три часа. При просадке немедленно выключать ключ и блокировать повторный нагрев до напряжения не ниже 3.7 В при выключенном нагревателе. Делитель батареи — 5 кОм / 5 кОм на GPIO35. Интервал и защёлка сохраняются в RTC через DeepSleep; при потере истории нужны полный интервал и подтверждение 3.7 В заново.
- Перед глубоким сном ESP32 обязательно переводить модем в сон, включая пути обработки ошибок.
- Не выдавать геометрический профиль за готовую аэродинамическую калибровку. Неизвестные коэффициенты, распиновку и аппаратные ограничения явно отмечай.

## Изменения и совместимость

- Сначала изучай реализацию и потребителей; сохраняй изменения пользователя и ограничивай diff поставленной задачей.
- Все импорты располагай на уровне модуля, вне функций, методов и циклов, в том числе в примерах.
- Не переименовывай существующие переменные без необходимости. Имена делай предметными и лаконичными, классы называй в CapWords, функции и методы — по действию; `_` используй для внутренних функций и методов.
- Пиши компактно, без дублирования, лишних временных переменных и очевидных комментариев. Комментарии нужны для причин, ограничений и математики, докстринги — для контрактов.
- В модуле располагай импорты и константы, структуры данных, публичный интерфейс, затем внутренние функции. В классе: поля и `__init__`, публичные методы и свойства, затем внутренние; соблюдай зависимости определений.
- Между функциями и классами верхнего уровня оставляй две пустые строки, между методами — одну. Внутри функций пустые строки разделяют самостоятельные смысловые этапы; не отделяй ими `return` автоматически.
- Учитывай целевую версию MicroPython: не переноси возможности CPython и синтаксис, не поддерживаемый прошивкой, без проверки совместимости.
- Не добавляй зависимости и попутный рефакторинг без необходимости для задачи.
- Избегай блокирования цикла асинхронных задач, лишних выделений памяти и накопления всех измерений, если достаточно текущих сумм и счётчиков.
- Не изменяй входные массивы без явного контракта; избегай повторных вычислений, преобразований и копирований.

## Проверки

- Для изменений поведения проверяй значимые сценарии; аппаратные проверки отделяй от проверок на компьютере.
- Основная команда: `python3 -m unittest discover -s tests -v`. Зависимости для неё не требуются.
- CPython не может выполнить пример целиком: он использует `machine`, `utime`, `aioble`, `bluetooth` и отсутствующий в репозитории `utilities`.
- Проверка синтаксиса CPython сама по себе не доказывает совместимость с MicroPython, корректность AT-команд или работу оборудования.
- Перед завершением отдельно проверь архитектуру и контракты, стиль, данные и производительность; просмотри итоговые изменения и выполни `git diff --check`.
- В результате перечисли выполненные проверки и явно укажи проверки, недоступные без платы, датчиков, модема или нужной прошивки.
