# Анемометр Пито на ESP32 и SIM800

Первая версия прошивки MicroPython для LilyGO TTGO T-Call с SIM800L и IP5306.
Два BMP280 измеряют давление полного и статического каналов профиля
из `stl/lower.stl`. MQTT и HTTP выполняются встроенными средствами модема
через AT-команды; внешние Python-библиотеки не нужны.

## Подключение и загрузка

Требуется MicroPython для обычного ESP32 с `asyncio`, `machine`, `utime`,
`json`, `struct`, `math` и `binascii`. Используются `asyncio.sleep_ms()` и
`asyncio.wait_for_ms()`. Перед загрузкой сверьте `config.py` с ревизией платы:
значения по умолчанию соответствуют T-Call SIM800L IP5306 20200811.
Платы с AXP192 требуют другого управления питанием и измерения батареи.

| Сигнал | Значение по умолчанию |
| --- | --- |
| BMP280 SDA / SCL | GPIO21 / GPIO22, общая шина I²C с IP5306 |
| BMP280 полного давления | `0x76`, SDO на GND |
| BMP280 статического давления | `0x77`, SDO на постоянных 3V3 |
| BMP280 VDD | GPIO18, общая земля |
| BMP280 VDDIO / CSB | постоянные 3V3, для общей шины с IP5306 |
| Питание датчиков | GPIO18, HIGH — включено, LOW — выключено, `Pin.DRIVE_3` |
| UART SIM800 TX / RX со стороны ESP32 | GPIO27 / GPIO26, 9600 бод |
| SIM800 PWRKEY / POWERON / RESET | GPIO4 / GPIO23 / GPIO5 |
| SIM800 DTR | GPIO32; для ревизии без DTR указать `None` |
| Индикатор платы | GPIO13, выключен при LOW |
| IP5306 | адрес `0x75` |
| Оттаиватель | GPIO19 → транзисторный ключ, HIGH — нагрев, LOW — выключен |
| Измеритель напряжения батареи | внешний делитель на GPIO35; включить в настройках после подключения |

Загрузите в корень файловой системы ESP32 все девять файлов:
`main.py`, `app.py`, `config.py`, `board.py`, `bmp280.py`, `sim800.py`,
`telemetry.py`, `remote_settings.py`, `heater.py`. Каталоги `examples`, `tests`
и `stl` на плате не нужны. `flugerp.example.json` предназначен для HTTP-сервера.
После перезапуска автоматически запускается `main.py`.

Питание датчиков включается перед инициализацией I²C, затем выдерживается
`SENSOR_POWER_ON_DELAY_MS=10` мс. После завершения всех задач перед DeepSleep
сначала SCL (GPIO22), затем SDA (GPIO21) переводятся в open-drain LOW без
внутренних подтяжек и удерживаются. Только если чтение обоих выводов возвращает
LOW, GPIO18 переводится в LOW и удерживается. Если настройка линий, удержание
или проверка уровня не удались, питание датчиков оставляется включённым
с диагностикой в консоли. При пробуждении SDA/SCL остаются удержанными до
включения GPIO18 и выдержки 10 мс; затем шина освобождается и настраивается I²C.
`Pin.DRIVE_3` — максимальная сила драйвера ESP32, в документации MicroPython
для неё указано 40 мА. Это не стабилизатор и не ограничитель тока:
потребление датчиков, модулей и пусковой ток должны укладываться в возможности
GPIO; при необходимости питание коммутируют внешним ключом.

По даташиту Bosch (таблицы 2 и 12), в нашем forced mode 1 Гц, P ×16 / T ×2:

| Потребление микросхем | Один BMP280 | Два BMP280 |
| --- | --- | --- |
| Среднее, типовое / максимальное | 24.8 / 36.85 мкА | 49.6 / 73.7 мкА |
| При измерении давления, типовое / максимальное | 0.72 / 1.12 мА | 1.44 / 2.24 мА |
| Sleep при 25 °C, типовое / максимальное | 0.1 / 0.3 мкА | 0.2 / 0.6 мкА |

Для двух самих микросхем GPIO18 имеет достаточный запас рабочего тока.
Это не оценка готовых плат: стабилизатор, индикатор, подтяжки и заряд входных
конденсаторов добавляют нагрузку. При питании через стабилизатор проверьте
напряжение на самом BMP280, а не только на входе модуля. У каждого датчика
нужны рекомендованные Bosch конденсаторы 100 нФ на VDD и VDDIO к земле.

Таблица подключения выше относится к отдельным микросхемам с доступными
VDD и VDDIO. Bosch разрешает отключать VDD при включённом VDDIO: интерфейс
остаётся высокоомным. Это позволяет оставить общую с IP5306 шину I²C
подтянутой к постоянным 3V3. CSB и SDO датчика 0x77 подключаются к VDDIO.

Если на готовом модуле VDD и VDDIO объединены, напрямую выключать его питание
при высоких SDA/SCL нельзя: Bosch предупреждает о возможном повреждении через
защитные диоды. Прошивка удерживает SDA/SCL в LOW перед отключением и весь сон,
но CSB и SDO датчика 0x77 на таком модуле тоже должны быть подключены к его
коммутируемому VDDIO, а не к постоянным 3V3. Подключение и уровни при сбросе,
переходе в сон и пробуждении проверяются на реальной плате; схема модулей
пользователя пока неизвестна. Раздельные VDD/VDDIO либо развязка шины позволяют
избежать зависимости безопасности отключения от удержания GPIO.

Общая шина с IP5306 остаётся LOW весь сон, новые обращения к нему выполняются
только после включения датчиков и восстановления I²C. Внешние подтяжки при
этом продолжают потреблять ток: для одной пары 4.7 кОм к 3.3 В это около
1.4 мА суммарно. Для минимального потребления может быть выгоднее оставить
датчики постоянно запитанными в штатном sleep и не удерживать шину в LOW.

SIM-карта T2 должна быть активирована, с доступом к GPRS и отключённым PIN.
Настройки APN вынесены в `config.py`; исходное значение — `internet.tele2.ru`,
имя пользователя и пароль пустые. Для SIM800 требуется питание, рассчитанное
на токовые импульсы GSM, и подключённая GSM-антенна.

## Рабочий цикл

1. Снимается удержание GPIO после предыдущего сна. Для IP5306 включается
   keep-on, чтобы питание ESP32 не отключалось при малой нагрузке во сне;
   питание BMP280 включается через GPIO18 с максимальной силой драйвера.
2. Отдельная задача в течение 60 секунд запускает оба BMP280 раз в секунду.
   Используется forced mode: T ×2, P ×16, ожидание преобразования 50 мс.
   Учитываются только полные пары измерений одного цикла.
3. Параллельно включается SIM800, выводится `ATI`, проверяется поддержка
   MQTT и открываются GPRS bearer 1 и MQTT-сессия.
4. После измерения отправляется JSON в топик `fluger_p` сервера
   `212.34.149.112:1883`. Доступ задан в `config.py` по исходному ТЗ.
   Публикация QoS 1 считается успешной после `+SMPUB: <id>,0`, одного `OK`
   недостаточно. При ошибке допускается ещё одна сессия; возможны дубликаты.
5. Встроенный HTTP-клиент читает `http://212.34.149.112:80/flugerp.txt`.
   Ожидается JSON с длительностью сна и командой нагрева, описанный ниже.
   При HTTP-ошибке, недоступном файле, пустом, слишком большом или некорректном
   ответе применяются пять минут сна и выключенный нагрев. Настройка читается
   заново в каждом цикле и не записывается во flash.
6. SIM800 выключается командой `AT+CPOWD=1` до ответа `NORMAL POWER DOWN`.
   При ошибке предпринимается резервный сон по DTR. POWERON опускается,
   DTR поднимается, UART отключается.
7. После измерений и завершения работы модема выполняется запрошенный нагрев,
   если позволяют напряжение батареи и трёхчасовой интервал. В конце ключ
   выключается. SDA/SCL удерживаются в LOW и проверяются, затем при успешной
   проверке питание датчиков на GPIO18 выключается. GPIO, включая LOW ключа
   нагрева, удерживаются; ESP32 входит в DeepSleep.

Рабочее окно связи ограничено 240 секундами, завершение модема — ещё
15 секундами. Разрешённый нагрев добавляет до 300 секунд перед сном.
Даже при отсутствии датчиков или сети устройство переходит в сон.
При отсутствии полных пар MQTT содержит `null` вместо показаний.
Ошибки, перехваченные в рабочем цикле, не препятствуют подготовке GPIO и сну.

Пять минут — длительность **сна после работы**, а не точный интервал между
публикациями: к ней прибавляются минута измерений и затраты на связь.
Измените `DEFAULT_SLEEP_MINUTES`, если нужен другой резервный период.

## JSON-файл управления

Адрес сохранён: `http://212.34.149.112:80/flugerp.txt`, но содержимое теперь JSON.
Скопируйте `flugerp.example.json` на сервер под именем `flugerp.txt`:

```json
{
  "sleep_minutes": 5,
  "heater": {
    "enabled": false,
    "duration_s": 60
  }
}
```

`sleep_minutes` — целое число минут сна, 1..1440. `heater.enabled=true`
запрашивает один цикл оттаивания после текущих измерений, `false` запрещает
его. `duration_s` — целое число секунд, 1..300; по умолчанию 60.
Если оставить `enabled=true`, запрос повторяется на каждом пробуждении,
но исполнится только после окончания ограничения в три часа. Для отмены
следующего цикла установите `false`. Команда уже выполняющегося нагрева
завершается по таймеру или защите батареи; файл во время нагрева не опрашивается.
Файл ограничен 512 байтами. Старое содержимое из одного числа больше не
принимается; некорректные типы и пределы приводят к резервным настройкам.
Порог батареи и трёхчасовой интервал задаются локально в `config.py`, JSON их
не изменяет.

## Оттаиватель и защита батареи

GPIO19 свободен в используемой конфигурации T-Call SIM800L IP5306. Он управляет
только затвором/входом ключа. Для N-канального MOSFET нижнего плеча подключите
резисторы между плюсом питания нагрева и стоком, исток — к общей земле.
Затвор соедините с GPIO19 через 100..330 Ом и подтяните к земле через
47..100 кОм, чтобы ключ оставался выключенным при сбросе и до запуска Python.
Нужен MOSFET, у которого сопротивление открытого канала нормировано при
управлении 3.3 В или ниже. Питание резисторов не берётся с GPIO.

Для одного резистора 22 Ом ток равен `U / 22`, мощность — `U² / 22`.
При питании от одной Li-ion ячейки это примерно 150 мА / 0.50 Вт при 3.3 В
и 191 мА / 0.80 Вт при 4.2 В. Две параллельные ветви удваивают суммарные ток
и мощность. Номинальную мощность резисторов и допустимый нагрев камер выбирают
с запасом по реальному напряжению питания; его значение пока не подтверждено.

Встроенный индикатор IP5306 даёт только грубый процент заряда. Для проверки
порога **3.3 В** измеряется напряжение самой ячейки через внешний делитель:
`BAT+ → 5 кОм → GPIO35 → 5 кОм → GND`; между GPIO35 и GND — 100 нФ.
Коэффициент делителя — 2.0, собственный ток при 3.3..4.2 В — 0.33..0.42 мА.
Нельзя подавать напряжение полностью заряженной ячейки напрямую на ADC.
После монтажа установите `BATTERY_ADC_PIN=35` и проверьте показания по
мультиметру, при необходимости изменив `BATTERY_ADC_CALIBRATION`.
По умолчанию `BATTERY_ADC_PIN=None`: нет подтверждённого измерителя, нагрев
запрещён. `AT+CBC` не используется вместо напряжения ячейки: на плате питание
SIM800 формируется собственной цепью и не является достоверным измерителем BAT+.

Перед проверкой батареи ключ выключается, выдерживается одна секунда без
нагревателя и после завершения работы модема. Напряжение в этом состоянии
измеряется усреднением 16 отсчётов. Во время нагрева используется один отсчёт
`ADC.read_uv()` сразу после включения и далее с паузой 100 мс между проверками;
чтение и подготовка ADC занимают дополнительное время. Усреднение под нагрузкой
не применяется, чтобы не скрыть краткую просадку. При значении ниже 3.3 В,
неизвестном/недопустимом напряжении или ошибке ADC ключ выключается сразу
после обнаружения и повторный нагрев блокируется. Это программный контроль,
не аппаратная отсечка с нулевой задержкой.

После такой остановки напряжения 3.3..3.69 В недостаточно: блокировка снимается
только при **не менее 3.7 В с выключенным нагревателем**, после паузы одной
секунды. Даже после восстановления нужно дождаться окончания трёхчасового
интервала. При штатном окончании нагрева без просадки следующему циклу
достаточно обычного порога 3.3 В. Обе защиты действуют независимо.
Ключ выключается в `finally`, в начале `main.py` и перед DeepSleep; при
сбросе до старта Python выключение обеспечивает внешняя подтяжка затвора.

Между стартами нагрева выдерживаются минимум 10800 секунд. Запись с контрольной
суммой в `RTC.memory()` сохраняет интервал и защёлку батареи и переживает
DeepSleep и мягкий сброс. Защёлка заранее устанавливается **до** подачи
нагрузки и снимается после штатного завершения, уже при выключенном ключе.
При просадке, прерывании или сбросе во время нагрева она остаётся установленной.
Даже прерванный цикл занимает трёхчасовой интервал. При первой установке,
потере/повреждении истории, переходе со старого формата записи или откате
часов отсчитываются три часа заново и требуется подтверждение 3.7 В без
нагревателя. Ошибка сохранения RTC запрещает старт. Приложение использует весь буфер
RTC user memory и не синхронизирует часы с внешними источниками; вручную
переводить RTC вперёд во время эксплуатации нельзя.

Нагрев выполняется после минутного окна, чтобы не искажать уже переданные
температуру и давление. Результат (`disabled`, `cooldown`,
`battery_lockout`, `complete`) выводится в консоль.

## Встроенный MQTT SIM800

Реализован набор команд из SIMCom *SIM800 Series MQTT Application Note V1.03*:
`AT+SAPBR`, `AT+SMCONF`, `AT+SMCONN`, `AT+SMSTATE`, `AT+SMPUB`, `AT+SMDISC`.
Для SIM800 адрес и порт объединяются в `URL`, параметр времени называется
`KEEPALIVE`, а сообщение передаётся аргументом `AT+SMPUB=<topic>,1,0,<message>`.
Кавычки JSON экранируются обратной косой чертой в строке AT-команды.
Совместимость этого экранирования с конкретной прошивкой проверяется на плате.

Это отличается от `examples/main_sim7000.py`, где SIM7000 принимает длину
сообщения, приглашает `>` и затем получает отдельный блок данных. Точная
прошивка пользовательского модема неизвестна: при первом запуске проверьте
ответ `ATI`, успешность `AT+SMCONF=?` и получение JSON на брокере. Если команда
не поддерживается, журнал укажет её имя без аргументов с паролями.
Программного MQTT-клиента и автоматического переключения на другой протокол нет.

## Аэродинамическая калибровка

Расчёт использует `ρ = p_static / (287.05 × (T + 273.15))` и
`v = sqrt(2 × max(Δp − offset, 0) / (ρ × Cp))`.
Температура BMP280 используется как приближение температуры воздуха.
Сначала усредняется перепад, затем вычисляется скорость: отсечение шума
перед усреднением создавало бы положительное смещение около нуля.
При перепаде ниже `−NEGATIVE_PRESSURE_TOLERANCE_PA` скорость не вычисляется;
отрицательный перепад не заменяется модулем.

В STL есть только поверхность: габариты в координатах модели
171.5 × 52 × 26, расположение каналов давления и калибровочная характеристика
в нём не заданы. Без них невозможно подтвердить реальный `Cp` профиля.
`PROFILE_PRESSURE_COEFFICIENT=1.0` — предварительная модель трубки Пито.

Для калибровки запишите среднюю разность показаний в неподвижном воздухе
в `PRESSURE_ZERO_OFFSET_PA`. Затем на известной скорости `v_ref` определите
`Cp = 2 × (Δp − offset) / (ρ × v_ref²)` и проверьте несколько скоростей.
Только после этого установите `WIND_CALIBRATED=True`. Два абсолютных BMP280
имеют собственные смещения и температурный дрейф: различимость слабого ветра
и итоговую погрешность нужно оценить экспериментально.

## Проверки и первый запуск

На компьютере, без установки зависимостей:

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q main.py app.py config.py board.py bmp280.py sim800.py telemetry.py remote_settings.py heater.py
git diff --check
```

Тесты используют имитации UART, I²C и GPIO. Они проверяют компенсацию BMP280,
математику усреднения, ответ MQTT, чтение JSON по HTTP, параллельность,
аварийный сон, пороги 3.3/3.7 В, сохранение защёлки батареи через перезапуск,
трёхчасовой интервал и выключение нагрева при просадке, отмене задачи и исключении.
Они не доказывают работу радиосвязи, совместимость прошивки и ток потребления.

Для пробного запуска откройте последовательную консоль ESP32, перезапустите
плату и проверьте `ATI`, примерно 60 успешных пар, сообщение о подтверждении
публикации и реальное содержимое `fluger_p` на брокере. Затем проверьте чтение
периода сна, `NORMAL POWER DOWN`, пробуждение ESP32 и новый цикл.
Отдельно проверьте работу от батареи, ток во сне и случаи отсутствия SIM,
одного BMP280, сети и HTTP-файла. Начальную проверку поправки нуля выполняйте
с обоими каналами под одинаковым давлением.
Перед подключением резисторов проверьте GPIO19 без нагрузки, запрет нагрева
при неизвестном/низком напряжении и сохранение ограничения через DeepSleep.
